# SpokyTime — ротация ауры, вытащенная из ZenithDLC

Это самодостаточный перенос режима **`SpokyTime`** из модуля `Aura` (killaura) клиента ZenithDLC:
нейросетевая «человеческая» доводка прицела вместо обычного снапа/линейного сглаживания.

Что извлечено и проверено:

| В моде | Здесь | Состояние |
|---|---|---|
| `Motor` (1217 строк обфусцированного кода) | `java/spooky/SpookyModel.java` + `SpookyRotation.java` | forward-pass совпадает с эталоном до 3e-15 |
| `models/motor.json` (49 МБ JSON) | `model/motor.bin` (6.7 МБ, little-endian) | пересобирается из JSON скриптом |
| `AuraModule` → `BcCameraTestnerv` → `Motor.method3659()` | `SpookyRotation.tick(...)` | логика состояния воспроизведена строка в строку |
| `Rotation` / `RotationUtils` | `java/spooky/Rotation.java`, `MathX.java` | — |

Никаких зависимостей: JDK 17+ (в CI проверяется на 21), без Minecraft, без Gson, без Lombok.

## Быстрый старт

```java
SpookyModel model = SpookyModel.load(Path.of("model/motor.bin"));     // 1 раз
SpookyRotation aim = new SpookyRotation(model, MathX.pixelStep(0.5), new Random());

// каждый тик, пока цель валидна
Rotation next = aim.tick(currentRotation, target, playerState, tickId);
applySilentRotation(next);   // см. «Как применять» ниже
```

`target` — AABB цели, `playerState` — глаза, зажатые клавиши, onGround/sprint/sneak,
прогресс кулдауна атаки и `ticksSinceLastAttack`, `tickId` — номер тика (в MC `player.age`).

Демо и самопроверка:

```bash
cd port/spookytime-rotation
python3 tools/convert_model.py          # motor.json -> model/motor.bin + проверка эталона
javac -d out $(find java -name '*.java')
java -cp out spooky.SelfTest model/motor.bin
```

## Как это работает

1. **Геометрия.** Из глаз игрока считаются углы на центр хитбокса цели, дистанция и
   разброс углов по 8 вершинам бокса (минимум/максимум по yaw и pitch).
2. **47 признаков.** Текущее отклонение прицела, ошибка «на глаз», экстраполяция позиции
   цели на `latency+1` тиков, скорость/ускорение цели, попадание внутрь бокса,
   собственные прошлые движения мыши (2 тика), счётчики «стоял на месте»/«дёрнулся в
   обратную сторону», пики скорости, ввод с клавиатуры, состояние игрока, кулдаун атаки
   и факт удара в прошлом тике. Полная таблица — в [SPEC.md](SPEC.md).
3. **Политика.** `MLP(47→256, SiLU) → MLP(256→256, SiLU) → GRU 2×256 → головы`
   (`pi`, `mu`, `log_sigma`, `rho`, `pause`) — смесь из 5 двумерных гауссиан
   (yaw/pitch в asinh-масштабе) плюс отдельная вероятность «ничего не делать».
4. **Сэмплирование.** С вероятностью `sigmoid(pause)` тик пропускается. Иначе выбирается
   компонента смеси, сэмплируется пара значений, переводится через `sinh` в градусы и
   ограничивается `max_cmd` (130°/31°).
5. **Огибающая.** По модулю последних двух шагов в «пикселях мыши» выбирается лимит из
   таблиц `edges/caps` — так модель не может резко дёрнуть больше, чем человек.
6. **Квантование.** Команда переводится в целое число пикселей мыши
   (`step = f(sensitivity)`), остаток переносится на следующий тик (`act_residual`).
   Именно поэтому на выходе получаются «человеческие» шаги по 0.15° при sens 0.5.

Ключевая деталь, на которой легко споткнуться при переносе: после входных слоёв модели
стоит **SiLU** (`x / (1 + e^-x)`), а не сигмоида — в обфусцированном коде это выглядит
как дележ на `1 + exp(-x)` и легко читается неправильно. С сигмоидой golden-тики
расходятся на единицы, с SiLU — совпадают до 1e-15.

## Как применять

В моде ротация **тихая**: она подменяет yaw/pitch в отправляемых пакетах движения, камера
игрока не крутится. Пайплайн такой:

- `RotationManager` раз в тик (после ввода) берёт из очереди заявку с TTL = 1 тик и
  подставляет результат в `currentRotation`, `pitch` зажимается в ±90;
- когда заявок больше нет, мод доводит значение этим же движком к реальной ротации игрока,
  и как только расхождение ≤ **9°** — синхронизирует камеру игрока с тихой ротацией и
  отпускает её (иначе клиент «залипает» и следующий ввод мыши прыгает);
- на каждый тик — максимум один вызов `tick(...)` (в моде это гарантируется запоминанием
  результата по `player.age`).

Готовый скелет интеграции — `java/spooky/example/MinecraftHook.java.example`.

## Как перенести в другой чит

1. Скопировать `java/spooky/*.java` и `model/motor.bin` в проект (пакет можно переименовать).
2. Реализовать три структуры данных: AABB цели, состояние игрока, текущая ротация.
   Ничего специфичного для Minecraft внутри порта нет.
3. Отдавать **тихую** ротацию в свой rotation-менеджер (или напрямую в пакеты движения).
   Если в клиенте ротация «жёсткая» (крутит камеру) — поведение будет другим: модель
   обучалась на записях мыши, где прицел доводится рывками.
4. Сбросить состояние (`reset()`) при смене цели, телепорте, респавне, загрузке мира —
   иначе GRU продолжит «двигаться» по старой истории.
5. Выбрать шаг пикселя: `MathX.pixelStep(sensitivity)` — 0.15° при sens 0.5. Если в целевом
   клиенте другая формула/чувствительность, поменяйте множитель (это единственный
   параметр, завязанный на настройку игрока).
6. Прогнать самотест: `SpookyModel.selfCheck()` должен дать < 1e-9.

## Что НЕ входит в перенос

Это только ротация. Остальное в моде живёт отдельно и его нужно портировать самому:

- выбор цели и сортировка (`safeTarget`, `distance`, FOV) — `AuraModule`;
- аим-поинт и рандомизация точки попадания (`AuraRandomizer`, обход стен,
  предсказание хитбокса через `PlayerSimulation`/`ReachV3`);
- логика атаки/кулдауна/крита (`cooldownMode`, `onlyCrit`, `smartCrit`);
- применение ротации в пакетах и синхронизация камеры — `RotationManager`.

Для справки: режимы `FunTime`, `GOWNO*` и `SpokyTime` в моде ведут в один и тот же
движок (`Motor.method3659()`); отличается только конфиг (`Class44` → `Enum1.FUNTIME`),
поэтому отдельной «споки-математики» в исходниках нет — вся разница в моделях/конфигах.

## Проверка

`motor.bin` содержит 2 эталонных тика из обучения (входные 47 признаков + ожидаемые
`pi/mu/log_sigma/rho/pause/hidden_out`). `SelfTest`/`selfCheck()` гоняет их через
forward-pass: расхождение сейчас **2.7e-15**. Это гарантия, что веса разложены и
перемножены так же, как в оригинале.

CI: `.github/workflows/port-selftest.yml` — пересобирает `motor.bin` из исходного JSON,
компилирует порт с `-Xlint:all` и гоняет самотест.

## Замечания

- Аура/killaura нарушает правила большинства серверов (SpookyTime, FunTime и т.п.) —
  аккаунт могут забанить. Это выдержка из кода для переноса, а не приглашение к использованию.
- Модель обучалась на записях живой мыши конкретного игрока/набора сессий, поэтому
  «характер» прицела — её свойство; подгонять под себя можно только шаг и огибающую,
  не трогая веса.
